### 3. Собственные функции jrpm (предыдущие 5 функций, d4c45740) → уже в ветке jrpm

Параллельная загрузка (несколько зеркал + 4 параллельных сессии), автоматическая группировка, подсказка строительства, глобальный AI (ScriptGlobal + GlobalAI), настройки зеркал/сервера контента.

## Стратегия сетевой игры («новая версия для удобной игры по сети»)

- jrpm — **tagged-версия**: `IsNetworkCompatibleVersion` требует полного совпадения строки ревизии → **клиент jrpm подключается только к серверу jrpm**, полностью изолирован от jgrpp 0.73.x / pxp;
- **Серверное послабление**: сервер jrpm дополнительно принимает клиенты `jgrpp-*` и `pxp*` (`IsJgrppNativeNetworkRevision` / `IsPxpNetworkRevision`, версия NewGRF должна совпадать);
- Таким образом: хост jrpm открывает сервер = только для игроков jrpm (по умолчанию); при необходимости совместимости со старыми клиентами без изменения конфигурации принимает игроков jgrpp/pxp.

## Сборка и проверка (выполняется на машине пользователя)

```bash
# Первый раз (требуется CMake + зависимости, см. COMPILING.md)
cmake -B build ..
cmake --build build -j
# Результат: build/openttd-jrpm.exe
```

Приоритет проверки:
1. `openttd-jrpm -v` показывает `jrpm-0.1.0`;
2. Одиночная игра 1-2 года (слияние затрагивает крупные изменения train/airport + версия сохранения может быть увеличена из-за allow_modify_airports и т.д.);
3. После открытия сервера: подключение клиента jrpm ✓; попытка подключения оригинального клиента jgrpp 0.73.x (ожидается успех, если NewGRF совпадают);
4. Смена локомотивов: добавление приказов на расцепку/сцепку поезда, проверка независимого управления после расцепки; модульные аэропорты: включение `station.allow_modify_airports` и изменение планировки аэропорта;
5. Регрессия предыдущих 5 функций (параллельная загрузка, автоматическая группировка, подсказка строительства, GlobalAI).

## Известные риски

- **Не проверено на реальном железе**: код после слияния+модификации не компилировался на данной машине (нет цепочки инструментов), при первой компиляции могут быть пропущенные изменения интерфейсов (особенно серия крупных изменений aircraft/airport/train);
- Версия сохранения: px-patch мог увеличить SLV (M9 упоминает savegame version gate), сохранения jrpm и jgrpp 0.73.x могут не читать друг друга (следуя конвенции jgrpp, обратная совместимость с trunk сохранениями);
- Слияние привносит всю историю pulsexlb, для отслеживания принадлежности функций используйте `git log --oneline pulsexlb/px-patch`.

## Журнал слияний: 2026-09-28 (jgrpp-0.73.3 + px-patch 2609.x)

> Коммиты слияния: jgrpp 94 коммита (до `jgrpp-0.73.3`) + px-patch 113 коммитов (до после `pxp-2609.10`).

**Новое:** от pulsexlb — перевозка автомобилей (RoRo, см. Функции), 128 типов груза (CargoTypes на Uint128, через XSLFI_CARGO_TYPES_128), партия исправлений расцепления/сцепления и улучшения расписаний; от jgrpp — перетаскивание заказов/двойной клик, двухконцевые суда (XSLFI_DOUBLE_ENDED_SHIPS) и множество общих исправлений.

**Ключевая обработка конфликтов:** слой сохранения pulsexlb основан на старой системе макросов SLE_, тогда как jrpm/jgrpp 0.73.3 использует VarFileType/VarMemType + VarTypes; все конфликты saveload/ и sl/ переписаны в современной системе с добавлением поддержки U128 (VarFileType::U128=13, VarMemType::U128, SLE_UINT128); зарезервированные jrpm версии 367/368 сохранены, новые upstream-версии сдвинуты в 369/370; совместимость с upstream-сохранениями идёт через подблок XSLFI_UPSTREAM_VERSION; CT_VEHICLES строкой, сравнение grfid через GrfID, консольные блоки autogroup + RORO_DEBUG_COMMANDS сохранены.

**Состояние:** сборка MinGW ninja пройдена, артефакт `build/openttd-jrpm.exe`; быстрый тест новой игры пройден.
