### পোর্টিং কঠিনতা প্রতি আইটেম মূল্যায়ন

| কঠিনতা | তীব্রতা | ব্যাখ্যা |
|---|---|---|
| **存档体系 পুনর্লিখন** | 🟠 মাঝারি | growth_tiles vanilla `DefaultSaveLoadHandler` + `SlSetStructListLength`/`SlObject` ব্যবহার করে, jrpm হলো `sl/` নতুন体系 (SlTableHeader/SlObjectSaveFiltered)। jrpm-এর NSL/SLE + **XSLF বৈশিষ্ট্য গেট** দিয়ে পুনর্লিখন করতে হবে (নতুন `XSLFI_TOWN_GROWTH_TILES`, সংস্করণ ১), পুরনো存档 প্রভাবিত হবে না |
| **Town স্ট্রাকচার এক্সটেনশন** | 🟢 কম | শুধু growth_tiles দুটি ম্যাপ নেওয়া হবে (**বাদ দেওয়া** CBTownInfo/বিজ্ঞাপন/তহবিল ফিল্ড——সেগুলি CM সার্ভার CityBuilder প্লে-নির্দিষ্ট); jrpm Town-এ ফিল্ড যোগ + town_sl.cpp存档 টেবিল মাউন্ট |
| **মূল্যায়ন লজিক** | 🟢 কম-মাঝারি | অধিকাংশই বিশুদ্ধ কুয়েরি (GetTileType/StationFinder/Town ক্যাশে/বাড়ি চেক), jrpm API বিদ্যমান; TownZone ব্যাসার্ধ অ্যালগরিদম (`squared_town_zone_radius`) jrpm ফিল্ড নামের সাথে মিলাতে হবে |
| **রেন্ডার পাইপলাইন** | 🟠 মাঝারি-উচ্চ | `DrawTileZoning` ভিউপোর্ট ড্র পাইপলাইনে সংযুক্ত করতে হবে——**তৃতীয় ব্যাচ হাইলাইটের সাথে TileHighlight রেন্ডার মেকানিজম শেয়ার করে**। হাইলাইট পাইপলাইন না থাকলে আলাদাভাবে তৈরি করতে হবে (পরামর্শ: **প্রথমে হাইলাইট, তারপর জোনিং**) |
| **স্প্রাইট রিসোর্স** | 🟠 মাঝারি | ১২টি প্যালেট `CM_SPR_PALETTE_ZONING_*` **কাস্টম স্প্রাইট** ব্যবহার করে, jrpm-এ নেই → বিদ্যমান প্যালেট স্প্রাইট দিয়ে প্রতিস্থাপন বা নতুন রিসোর্স যোগ করতে হবে |
| **ইভেন্ট হুক** | 🟠 মাঝারি | growth_tiles রেকর্ড cmclient-এর **ইভেন্ট বাস**-এর উপর নির্ভরশীল (event::HouseBuilt/HouseCleared/..., cm_main.cpp-এর Emit)। jrpm-এ এই মেকানিজম নেই → সরাসরি town_cmd.cpp-তে বাড়ি নির্মাণ/ভাঙার স্থানে হুক যোগ + NewMonth ঘূর্ণন (IntervalTimer) |
